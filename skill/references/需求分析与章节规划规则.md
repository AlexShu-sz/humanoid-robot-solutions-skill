## 提取与核验

### 1. 输入与内部记录

接受用户提供的项目描述、现场视频、图片、文档、表格和补充答复。按下列字段自动生成本项目的 `内部项目稿.md`，后续步骤更新同一份记录。

| 字段 | 值及单位 | 状态 | 来源定位 | 影响或待确认项 |
|---|---|---|---|---|
| 当前人工节拍（秒/件） | 单件 CT 待核实 | 待核实 | 现场视频文件名与时间点 | 补拍完整作业循环，核对计时起止与件数 |

状态使用「已确认」「现场观察」「计算估算」「方案建议」「待核实」「不适用」「冲突」。同一字段包含不同口径时分条记录，例如客户目标与实测节拍分别列出。已确认写明确认依据，估算写明公式、输入值与假设，不适用写明适用范围。

### 逐项版现场调研表

正式发布模板为《优必选_项目现场调研_Excel模板_V1.0.0.xlsx》。

- 在现有「本次改造范围」或内部项目稿分开记录最终自动化范围、首期必验动作、首期允许保留的人工动作。对照动作流程、下料和设备交接核验分工与等待时间。首期范围待确认时列两条候选及成立条件。模拟阶段时长与目标节拍标注为模拟采用值。


- 从「现场调研」的项目基本信息区逐字读取客户名称和项目名称，并读取地址、行业、预计导入时间、联系人及项目目标，仅记录一次。区分项目名称、工位名称和工位编号。源表已有名称时逐字沿用；视频观察只用于描述现场。按「工位调研」区块读取各工位。通过「工位编号」或工位名称识别区块，字段按「细项」取「调研情况」，保留实际行号，兼容表尾复制的区块。工位编号重复或缺失时，按可确定的工位名称或区块顺序临时区分，提示项目方核对。
- 各工位分别记录现有节拍、目标平均和目标峰值，保留单位、单次件数、峰值持续时间及实测或估算口径。动作、照片、布局和接口仅归入资料覆盖的工位。未注明工位的附件先核对归属，对归属不明的资料标待核实。
- 「物料名称」可以引用「物料明细」的物料编号。由该明细读取共用的单件重量、尺寸与载具规格，保留其来源位置。工位内的单次抓取总重、是否含载具、抓取件数和码放方向按各工位单独记录。编号无法唯一对应时，将规格标待核实并保留对应工位。
- 直接出稿时，各工位的作业、指标和约束分别展示，可分栏或分页。补充问题涉及具体工位时同样带工位编号，项目公共问题标为项目级。明确填「不适用」且与其他证据一致的细项，跳过常规追问。

### 2. 取值与核验

- **资料定位**。用户答复记录原意，视频记文件名与时间点，图片记文件名及区域，文档记版本与页码，表格记工作表及单元格或行号。无法访问或辨认的附件记录状态和影响。
- **证据取值**。客户需求和范围以对应的书面要求或明确答复为依据。现场现状优先使用同工位、同规格的测量和作业记录。影像只记录可见内容。产品规格引用对应型号和版本，报价引用适用配置和有效期。案例数据只在有本项目依据时用于本项目。
- **视频计时**。先识别动作的起止、件数、批次和镜头连续性。覆盖完整可辨识循环时，记录样本次数、每次用时，以及等待、返工、换盘是否计入。批次用时换算秒/件时写明有效件数和计算口径。视频截断、剪辑或未覆盖完整循环时，保留可见动作与时间段，完整 CT 标待核实。
- **冲突与补充**。同一规格和口径出现矛盾时保留两条来源，标为冲突。以用户明确确认的更正更新字段，并复核相关选型、测算、验收和 PPT 页面。无法确认的冲突随稿记录。
- **追问与显示**。缺项会改变任务范围、技术路线或关键验收口径时，集中询问具体问题，并写明影响。用户要求直接出稿时，给出条件化建议并保留待核实项。内部字段应有状态，展示时按模板规则将无法核实的内容显示为「★待核实补充」。

### 3. 字段提取与核验

#### 项目基本信息与客户需求

| 原字段 | 取值与核验 |
|---|---|
| 客户名称、工位名称、汇报时间 | 取自项目资料或用户描述。工位名称缺失时可用「暂名」描述可见任务。汇报时间以用户指定时间为准，未定时可以注明按制作月份填写。 |
| 客户背景 | 优先读取用户提供的公司和项目材料，核实企业主体及相关产品或业务。企业历史、股权、排名和客户配套用官网、年报或正式新闻稿核对。用当前表单、图纸与视频提炼项目工序、工件、与方案有关的 1–2 个现场事实和改造切入点。分别保留资料和视频时间点，集团信息仅用于集团概况，项目厂区和产品用途以现场材料或客户确认为准。完整现场作业流程归入场景与任务拆解。 |
| 核心需求 | 记录客户已确认的目标、痛点和约束。视频可见的动作与工程推断单独标记。班次、人数、人员流失率、年薪缺失时保留待核实。 |
| 关注点 1、关注点 2、关注点 3 | 以客户明确强调的约束为依据。工程上建议关注的事项标为方案建议。字数限制由模板填充规则处理。 |

#### 产品本体与末端选型

| 原字段 | 取值与核验 |
|---|---|
| 预计选型型号 | 根据任务与可访问的产品规格回填。区分候选与已确认，原表示例型号仅作字段示例。 |
| 单臂负载要求、工作半径要求 | 基于物料与末端质量、偏心条件、实测取放点和姿态包络。双臂任务分别核对单臂分担与协同限制。 |
| 移动方式 | 根据工位覆盖、通道与取放位置提取限制，再回填固定工位、轮式或双足等候选方式及成立条件。 |
| 末端工具需求、末端快换接口 | 根据物料形状、允许接触面、重量、表面状态及换型频次判断。型号和接口以对应资料核验。 |
| 预计机器人台数 | 分期记录。估算时列目标产量、有效工时、实测或假设 CT、并行与停机条件。缺少关键输入时保留待核实。 |

#### 场景、物料与人工任务

| 原字段 | 取值与核验 |
|---|---|
| 作业场景总览 | 按工位记录任务范围、设备、物料、SKU、节拍和精度。指标注明现状或目标。 |
| 作业对象（物料）、物料形态分类 | 从图纸、样件清单和现场资料提取名称、尺寸、重量、材质和表面状态。影像可描述外观。数值尺寸需已知标尺或测量依据。 |
| 物料来源、物料去向 | 记录已见的取放点、载具与交接方式。超出画面的上下游待核实。 |
| 工人作业动作拆解、岗位难点 | 逐项记录动作编号、对象、起止状态、时间点和可见异常。动作占比只在有完整且可计量的样本时填写。 |
| 当前人工节拍（秒/件）、当前班产量（件/班） | 优先使用现场实测和班产记录。计算估算注明有效作业时间、循环件数、损耗与换型假设。班次时长采用实际口径。 |

按视频识别动作与可定位的状态变化，再决定拆分数量。记录动作编号、时间段或关键帧、执行者、对象、状态变化与对应能力，供人工拆解和机器人等效作业共用。

#### 环境与改造条件

| 原字段 | 取值与核验 |
|---|---|
| 工位可用空间（长×宽×高 mm）、现有设备干涉 | 使用现场测量或图纸，区分外形空间和可作业空间。记录设备、挡板、托盘边及活动区域。 |
| 地面情况、现场光照、温湿度 | 影像记录可见状况。平整度、照度、温湿度等数值由勘测或现场记录核验。 |
| 安全要求 | 记录客户现场要求和已确认的防护条件。待评估的围栏、互锁或异常处理写入方案建议。 |

#### 系统与软件对接

| 原字段 | 取值与核验 |
|---|---|
| 现有上层系统、PLC / 控制器品牌、网络协议 | 取自设备清单、接口文件、可辨认铭牌或客户确认。系统和协议缺失时标待核实。 |
| 需对接的数据点 | 区分设备已提供的信号与方案拟新增信号。记录方向、触发条件和作用，信号表待接口确认后回填。 |
| 客户 IT 部门对接人、网络安全要求 | 由客户或项目资料确认。保留交付所需的联系人与权限约束。 |

#### 执行规划与商务

| 原字段 | 取值与核验 |
|---|---|
| 一期 POC 目标、一期验收标准 | 记录范围、样本、指标及判定方法，区分客户要求和建议。成功率、连续运行时长及 CT 采用双方确认的口径。 |
| 一期预计周期、客户期望上线时间、关键里程碑 | 区分客户时间窗口与工程估算。估算注明起算条件和资源依赖。 |
| 二期目标、三期目标 | 分期列覆盖任务、目标指标及台数依据。涉及百分比时记录基准、计算口径和验收方式。模板阶段示例作为方案框架。 |
| 一期预算上限、付款方式偏好、竞品接触情况 | 取自客户或商务记录。报价来源另列配置、税运、服务范围及有效期。未知预算标待核实，待询价用于报价状态。 |
| 是否需要运维/维保、是否需要培训 | 根据客户范围、合同或项目要求确认。可记录建议的对象、内容和周期。 |

#### 附件与缺项

逐项记录作业视频（全景 + 近景）、工位现场照片（至少 4 张角度）、物料样件照片（尺寸对比物）、产线布局图 / CAD、客户现有系统清单、客户提供的书面需求文档。标明文件名、覆盖范围及可读性。已有局部素材时写清缺失的视角或动作。各节「AI反馈」归入内部待确认清单，记录缺项、影响及补充方式。

### 4. 交给方案分析与 PPT 填充

筛选面向评审的内容时，保留能说明需求、技术路线、作业边界、风险或验收的现场信息。原始画面限制、识别过程和排版映射留在内部项目稿。只有证据缺口会影响判断时，才将其改写为具体待确认的工位条件、接口或验证项。

提取结束后检查关键字段是否有值或状态，来源是否可定位，单位及目标、实测与估算口径是否清楚。方案分析回填候选选型、任务分工和验证条件。PPT 生成阶段按《方案制作与交付规则》读取这些字段，并检查同一字段跨页一致。

### 读取现场材料

- 视频用宿主的视觉能力或可用工具抽取带时间点的关键帧，覆盖动作开始、交接、结束和异常。图片读可辨识内容。表格保留工作表、单位、版本和口径。文字保留关键约束出处。
- 素材不可读时，说明哪份资料和哪类信息受影响，请用户提供可读的关键帧、截图、摘录或表格导出，仅在需要据此做关键判断时等待。
- 案例可来自当前附件、项目文件或用户授权的资料库。索引只提供定位或摘要时，关键参数需用原件或当前项目证据核对。上传、搜索与生成只使用宿主实际可用的能力。

## 检索与补充

### 四类参考资料

四类资料按用途检索。优先读取本次附件和用户指定的路径，也可读取可访问的资料索引。项目采用目录组织时，可使用文末所列的相对路径。


先查本次指定附件、索引和配置路径，再使用当前平台可访问的检索工具读取候选资料。索引记录是定位线索，按文件实际用途选用。按实际适用性选取，记录文件名、版本及页码或表格位置。索引摘要用于定位，具体承诺核对原件。对四类资料分别记录「采用」「无匹配」「缺少文件」「无法访问」或「待核对」。发现多版本冲突时保留依据，并向项目方核实影响决策的差异。

资料不足时，给出有依据的工程条件、候选方案及验证动作。缺本体资料则列选型条件，缺末端资料则列夹持窗口和试验要求，缺案例可按现场证据分析，缺报价表则列配置范围并标记待询价。把可后补的配套资料和会影响当前决策的资料分开列出。历史配置与价格仅作参考，项目报价需匹配本次范围。

### 产品与商务页的取材

- 用户指定某份历史方案为版式参考时，提取信息层级和页面组织。产品图及规格以本项目候选型号的资料为依据。
- 核验产品资料的表内型号、配置、版本和工况。发现表名与表内型号不同，或尺寸、重量、自由度等数值冲突时，保留来源及差异并注明核验条件。影响适配的字段作为验证或追问事项。保持单臂、双臂、最大负载和额定负载等原有口径。
- 历史报价可参考工作包、范围、交付物、周期及税价的组织方式。当前项目引用金额前，核对适用配置、报价主体、币种、税运、服务范围和有效期。未取得适用报价时列出本项目工作包及计价所需信息，标记待询价。

### 汇总和导出客户补充信息

只把会影响范围、技术路线、设备配置、验收或报价的问题纳入关键清单。能从附件或参考资料确定的内容直接采用。按影响排序并合并重复问题。对客户展示可填写的问题及单位，内部资料库缺项可另提示项目组补齐。

有上述需客户补充的关键事项时，自动生成或更新可编辑的 `客户补充信息表.xlsx`，表头为「问题编号、类别、请确认的问题、影响的方案判断、客户填写、单位或口径、附件或依据」。多工位项目在问题编号后增加「工位」列。编号在本项目内保持稳定，答案与附件列留空。注明未知填「待确认」，不适用可写原因。按项目自动填写问题行。首稿和改稿均检查触发条件。直接出稿时同步交付条件化 PPT 和 Excel 补充表。已有表格沿用问题编号和客户答复。没有客户补充事项时省略空表。用户明确要求只交 PPT 时遵循其交付范围。

### Excel 回传

按问题编号与原清单匹配，读取客户填写、单位和附件依据。记录工作表与行号。空白和「待确认」保留待核实状态，有冲突时列出冲突证据。将新确认内容回填`内部项目稿.md`，复核受影响的选型、技术路线、测算和验收，更新对应 PPT 页。汇总本次变更及仍需确认的问题。

### 工作簿生成与回传读取

当前平台支持生成工作簿时，按上方表头导出可编辑的 `客户补充信息表.xlsx`。读取回传工作簿时，保留工作表及行号。当前平台只能生成内容时，输出按同一表头排列的待补问题供后续生成。

## 章节规划

基础模块必须覆盖，可以合并为同一章。按项目需要添加模块。多场景先分场景写清需求、流程及关键设计，再汇总共用架构与配置。

| 模块 | 触发条件 | 内容与检查 |
|---|---|---|
| 现状与需求 | 基础 | 交代工序、痛点、现场资料和改造范围。列工件规格、节拍、质量、空间及接口中真正影响设计的约束。明确本期不覆盖的动作和规格。 |
| 作业流程与技术方案 | 基础 | 写清触发、执行者、关键动作、到位判定、结果回传与异常去向。说明末端、工装、感知或定位如何应对关键约束。优先使用流程图、现场图和关键参数表。 |
| 可行性与验证 | 基础 | 明确哪些动作适合人形机器人、哪些依赖改造或配套设备、哪些目前应由人工保留。每个关键风险对应验证动作。需要 POC 时给样件、最难工况、顺序、记录指标及通过条件。未确认阈值标待确认。 |
| 布局与系统接口 | 多工位、跨设备或有系统联动 | 描述工位、作业面、动线和物料交接。列信号的发送方、接收方、继续条件、超时及异常处理。尺寸不足时用示意图并标明不可用于施工。 |
| 节拍与数量 | 需要评估产能或配置数量 | 定义 CT 起止、单位、取放、移动、等待、重试和并行条件。给负荷、可用能力、利用率假设和取整方法。缺关键输入则写公式与待测项。 |
| 设备清单与实施 | 需要确认配置、施工条件或责任边界 | 区分机器人、末端、工装、配套设备和软件，写清数量依据、供应边界、实施前提、验证及交付节点。 |

## 1.0 现场输入与回填

- 项目公共信息填写一次。一个工位使用同一张表内的公共区和工位区。多工位以工位编号区分，物料用工位编号和物料编号关联。证据缺工位归属时先核对归属，再写进正文。已有逐项调研表沿用现场可直接填写的字段，PPT 字段对应关系维护在内部项目稿。
- 节拍保留现场报数单位、基准或目标、平均或峰值及持续时间。秒／件、秒／束、件／小时分别保留。存在明确换算关系且使用同一工位、同一动作范围时，可补充换算。模拟和访谈来源明确标识。盖章验收值以有权确认的材料为据。
- 填第 4 页前核实客户相关行业或产品业务，并把调研表和视频中的项目、工序和关键现场事实提炼成背景段。采用可信项目材料中的准确介绍，明确集团概况及客户项目口径。无客户名则在封面与背景页对应位置写待确认。右侧展开核心需求，人工配置、班次和完整现状基准由动作拆解页承接。
- 视频、图纸、表单由工位编号合并。动作事实与口述或表单发生差异时，内部稿保留双方口径和定位。交付稿采用可核实描述，设备控制、触发、人员边界、末端与空间等影响判断的差异自动进入客户补充表。缺项 Excel 保留问题编号、工位、现有依据、所需回复和回复栏。已明确的值直接入稿。
- 信息不足时，把已观察到的现状、可以评估的改造点及需补的资料分别写清。已有工位图、尺寸或接口依据才展开到相应技术深度。设备交接信号与上位系统是两个独立字段。

- 核对产品资料正文所示型号、版本和配置。遇到同型号资料在尺寸、质量或精度上冲突，内部稿保留各值及出处，在正文明确待核影响。正式选型以明确适用的规格版本为准。
